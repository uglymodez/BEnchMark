# Memory Lab for Mac · 2.2

Нативный бенчмарк памяти для **Apple Silicon и Intel, macOS 12+**.
Чтение, запись и задержка случайного доступа в одном приложении
AppKit. Реальные измерения, отдельные замеры, сравнение с эталоном. Без сети,
внешних библиотек, прав администратора и выдуманного «общего балла».

## Что нового

- **Подробный график как в исходном примере**: чёрный фон, бирюзовая сетка,
  жёлтая линия чтения и зелёная линия записи. 16 интервалов на удвоение буфера:
  225 размеров до 64 MiB, 257 до 256 MiB, 273 до 512 MiB, 289 до 1 GiB.
  Линии соединяют соседние реальные замеры без сглаживания, подгонки или
  искусственных ступеней. Переходы зависят от архитектуры Mac и условий теста.
  Зелёная линия теперь означает запись, а не выполнение кода старой программы.
- **Компактная таблица сохранена**: только пять опорных размеров, несмотря
  на подробный график. Минимум, среднее и максимум относятся к повторам именно
  указанного размера. Проценты сравнивают только эти пять строк.

- **5 диапазонов**: 4 KiB, 64 KiB, 1 MiB, 16 MiB и выбранный максимум
  (64/256/512 MiB или 1 GiB). Пять строк: минимум, среднее арифметическое,
  максимум и относительная скорость отдельно для чтения и записи.
  Это пять опорных размеров буфера, **не физические уровни L1–L5**.
- **Относительная скорость** = среднее / самое высокое среднее той же операции
  среди пяти строк в полном прогоне × 100%. Чтение и запись имеют отдельные максимумы.
  100% не означает попадания в кэш или достижение теоретического пика.
  Проценты появляются только после полного прогона; у частичного они пустые.
- **Latency**: случайно перемешанная цепочка зависимых чтений. Наносекунды на
  обращение вместо пропускной способности; помогает увидеть, как меняется
  задержка с ростом рабочего набора.
- **Эталон**: сохрани завершённый прогон и повтори тест. Пунктир на графике и
  проценты в подробных вкладках показывают изменение на тех же размерах буфера.
  В пяти диапазонах проценты сравнивают диапазоны текущего прогона. Эталоны
  сохраняются между запусками, отдельно для каждой вкладки.
- **Разброс**: среднее в пяти диапазонах, медиана в подробных вкладках, полоса min–max, коэффициент вариации (CV) и все исходные
  замеры. Точки с CV > 5% отмечаются для повторной проверки.
- **Интерактивный график**: наведи курсор или выбери строку таблицы, чтобы увидеть
  точные значения. Интерфейс поддерживает системную светлую и тёмную тему.
- **Условия прогона**: живой статус энергосбережения и теплового состояния macOS;
  максимальное наблюдавшееся состояние и изменения питания записываются в отчёт.
- **CSV / JSON**: единицы измерения в каждой строке, исходные замеры, настройки,
  признак полного/частичного прогона. CLI поддерживает обратный порядок размеров.

## Сборка и запуск

```sh
xcode-select --install   # один раз, если Apple Command Line Tools ещё не установлены
bash build.sh
```

Или открой **«Собрать и запустить.command»**. Скрипт собирает нативное приложение,
проверяет ядро, подписывает bundle локальной ad-hoc подписью и открывает
`build/Memory Benchmark.app`. Приложение можно перенести в «Программы».
Для сборки не нужны Python, Homebrew или полный Xcode. Скрипт не скачивает
зависимости и сохраняет предыдущую сборку рядом с датой в имени.

Для приложения, работающего нативно на обеих архитектурах: `ARCH=universal bash build.sh`.

Для сборки без открытия окна: `MB_NO_OPEN=1 bash build.sh`.
Для другой архитектуры: `ARCH=x86_64 MB_NO_OPEN=1 bash build.sh` или `ARCH=arm64`.
Тестовый бинарник выполняется при совпадении архитектуры с хостом и для universal.
В universal-приложении macOS сама выбирает нужную архитектуру.

**Архив `downloads/MemoryBenchmark-Mac.zip` — старая версия 1.0.**
Готовая версия 2.2 находится в `downloads/MemoryLab-Universal.zip` по ссылке выше.
Архивы не пересобираются автоматически при изменении исходников; проверяй
версию и происхождение сборки. Для разработки остаётся workflow
`Memory Lab validation`, создающий артефакт `MemoryLab-Universal`.

Сборки ad-hoc не имеют подписи Developer ID и нотариализации Apple. При блокировке
скачанного приложения используй системное «Всё равно открыть» после попытки
запуска либо собери его локально. Отключать Gatekeeper или SIP не требуется.

## Четыре режима

| Режим | Что измеряет | Единица | Лучше |
|---|---|---|---|
| 5 диапазонов | Подробное чтение и запись; сводка пяти размеров, среднее и min/max | GB/s и % | Больше |
| Read RAM | Последовательное чтение NEON/SSE2, один поток | GB/s | Больше |
| Write RAM | Кэшируемая запись NEON/SSE2 с барьером | GB/s | Больше |
| Latency | Зависимые чтения случайной цепочки указателей | ns/load | Меньше |

Ось X — размер **рабочего набора**, от 4 KiB до выбранного предела. Четыре точки
на удвоение в подробных вкладках, 16 интервалов на удвоение в первой; шкала логарифмическая. Данные ограничены 1 GiB, код — 64 MiB;
GUI дополнительно ограничивает буфер ⅛ установленной RAM.
GB/s — десятичные гигабайты в секунду (10⁹), размеры — двоичные KiB/MiB/GiB.

| Профиль, одинаковый в GUI и CLI | Время одного замера, минимум | Замеров на точку |
|---|---|---|
| Быстрый / `quick` | 15 мс | 3 |
| Баланс / `standard` | 35 мс | 5 |
| Точный / `precise` | 60 мс | 9 |

В первой вкладке тест теперь дольше: только замеры чтения/записи занимают
примерно 20–26 секунд в быстром, 79–101 секунду в стандартном и 243–312 секунд
в точном профиле (от 64 MiB до 1 GiB). Подготовка, прогрев и обработка
результатов добавляют время. «Стоп» сохраняет
только полностью измеренные точки. Частичный прогон можно экспортировать,
но нельзя использовать как эталон.

## Методика MBM-2.0

Измерение выполняется в одном фоновом потоке с QoS User Initiated. macOS выбирает
ядро сама; закрепления за P-ядром нет. Память выровнена и заполнена до замера,
есть отдельный прогрев. Используется монотонный таймер. Чтение/запись сохраняют
явные 128-битные NEON/SSE2 обращения, которые компилятор не может удалить.
Запись заканчивается барьером; считаются полезные записанные байты, без
добавления трафика read-for-ownership. Запись не гарантирует попадание в DRAM.

**Latency:** один указатель в каждом 128-байтном слоте. Вставка каждого нового
узла после случайного существующего узла строит один замкнутый цикл без
повторений и без дополнительного массива перестановки. PRNG и seed фиксированы,
выбор позиции использует rejection sampling. 128 байт — фиксированный шаг
нагрузки, а не обнаруженный размер линии кэша. Каждый адрес зависит от предыдущего
чтения; `volatile` сохраняет все обращения. До замера обходится весь цикл.
Во время замера таймер и отмена проверяются каждые 1024 чтения.
Результат включает цикл, TLB, кэши и планировщик — это **не чистая задержка DRAM**.

Для каждой точки сохраняются исходные замеры в хронологическом порядке,
среднее арифметическое (GUI), медиана, минимум, максимум и CV = population stddev / mean × 100%.
Порог CV > 5% — практическая подсказка, не статистический тест и не доверительный
интервал. Проценты сравнения не доказывают значимость изменений.

Тест NOP-кода сохранён в CLI (`--mode execute` или `--mode all`); в первой вкладке GUI теперь чтение и запись. NOP-код генерируется только локально. Его объём / время обхода — **прокси потока
инструкций**, не прямая пропускная способность I-cache. Если JIT недоступен,
CLI сообщает о недоступности операции. Используется
[механизм Apple MAP_JIT](https://developer.apple.com/documentation/apple-silicon/porting-just-in-time-compilers-to-apple-silicon)
с единственным entitlement `allow-jit`.

Это не многопоточная пиковая пропускная способность, не тест GPU и не проверка
исправности RAM. Даже большой буфер не гарантирует обход всех системных кэшей.
Размеры кэшей читаются из `sysctl`; частоты CPU и отсутствующие сведения не
выдумываются. Результаты разных методик и программ напрямую не сравниваются.

## Сравнение с эталоном

1. Закрой тяжёлые приложения, выбери режим и профиль, выполни тест.
2. Нажми **«Сохранить как эталон»**. Это заменит только эталон текущей вкладки.
3. Измени интересующее условие и повтори прогон с теми же параметрами.
4. Сравни пунктир и новую кривую, разброс. В пяти диапазонах линии показывают
   средние, а проценты таблицы относятся к лучшему диапазону текущего прогона.
   В остальных вкладках проценты показывают изменение к эталону.

Сравнение включается только при совпадении методики, машины/ОС, режима, предела
буфера, времени и количества замеров, числа потоков и начального состояния
энергосбережения. Новый режим `Memory Ranges` с `sweep=dense-16-v1` не
совместим с прежним `Cache Speed` и редким прогоном 2.1 (`compact-5-v1`). В подробных вкладках положительный процент означает рост GB/s или снижение ns/load:
для задержки используется `(эталон − текущая) / эталон × 100%`.
Если во время прогона менялось питание, эталон не считается сопоставимым.
Нагрев и фоновые процессы всё равно могут различаться: состояние macOS не
является показанием датчика в градусах или доказательством троттлинга.

Эталоны хранятся локально в
`~/Library/Application Support/MemoryBenchmark/baseline-0.json` … `baseline-3.json`.
При чтении проверяются версия формата, значения и исходные замеры; статистика
пересчитывается. Повреждённый файл пропускается. Сохранение атомарное.

## CLI и формат данных

```sh
./build/memory-bench --mode latency --max-mib 256 --profile precise --format json > latency.json
./build/memory-bench --mode all --max-mib 64 --quick > results.csv
./build/memory-bench --mode read --max-mib 256 --descending --samples 5 --seconds 0.035
```

`--samples 1..9` и `--seconds 0.001..1` переопределяют профиль независимо от
порядка аргументов. Один замер даёт CV=0 по определению и не доказывает стабильность.
`--descending` помогает исследовать зависимость от порядка прогона; результат
не объявляется автоматически «правильнее» восходящего. Ctrl+C отменяет замер
между пакетами, возвращает код 130 и закрывает JSON, сохраняя завершённые точки.

Формат **schema_version 2** намеренно отличается от CSV версии 1:

- `median`, `minimum`, `maximum` и `sample_1` … `sample_9` используют `unit` строки.
- `total_sample_seconds` — сумма времени замеров без подготовки и прогрева.
- `iterations` — проходы всего буфера для GB/s, отдельные чтения для ns/load.
- `state` и доступность JIT записываются после завершения/отмены CLI.
- CSV-комментарии начинаются с `#`: `pd.read_csv(path, comment='#')`.
- JSON GUI и CLI хранит `metadata` и `points`; каждая точка содержит строковый
  `operation`, числовой `operation_id` и массив `sample_values`.

Начиная с GUI 2.1 схема 2 дополнена полем `mean` в каждой точке, сводкой
`range_summary` из пяти строк в JSON и столбцами `mean,relative_speed_percent`
в CSV. Сводка содержит `buffer_bytes` и отдельные `read`/`write` с минимумом,
средним, максимумом и процентом. Проценты отсутствуют у частичных прогонов.
Средние пересчитываются из `sample_values`, а не берутся из сохранённого итога.
В GUI 2.2 `points` содержит все промежуточные замеры подробного графика,
а `range_summary` — по-прежнему пять строк. В CSV у промежуточных точек
`relative_speed_percent` пустой, поскольку они не входят в сводку.
CLI сохраняет прежние подробные режимы и формат.

## Проверки и исходники

```sh
bash test.sh                  # C-тесты и Python 3 для контрактов CLI
SANITIZE=1 bash test.sh       # AddressSanitizer + UBSan, Linux
```

На macOS дополнительно проверяются сериализация отчётов, повреждённые данные и
совместимость эталона. CI содержит Linux и сборку universal на Mac Intel с `-Werror`,
проверкой обеих архитектур и подписи. Intel выполняет тесты и два реальных
latency-прогона и два компактных прогона в AppKit с сохранением/восстановлением эталона. Снимки светлой
и тёмной темы и отчёты включаются в артефакт. Отдельную нативную ARM-проверку
можно включить через Run workflow → `native_arm64`; она зависит от доступности
ARM-исполнителей GitHub. Компиляция ARM-части на Intel не равна её выполнению.
Это не заменяет проверку интерактивных действий на пользовательском Mac.

- `Sources/benchmark.c`, `.h`: четыре нагрузки, статистика и отмена.
- `Sources/main.m`: AppKit, график, условия прогона, эталон.
- `Sources/report.m`, `.h`: JSON-представление, валидация, CSV, сравнение.
- `Sources/cli.c`: CLI с тем же ядром и профилями.
- `Tests`: инварианты цепочки, статистика, экспорт и отмена.
