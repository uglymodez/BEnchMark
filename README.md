# Memory Lab for Mac · 2.3

Нативный бенчмарк памяти для **Apple Silicon и Intel, macOS 12+**.
AppKit, реальные измерения, исходные повторы, эталоны и CSV/JSON.
Приложение работает локально, без сети и внешних библиотек.

## Что изменилось в 2.3

- Вкладки доступны **во время теста**, включая «О программе». Результаты,
  настройки, прогресс и температура относятся к своему измерению; переключение
  не переносит точки в чужой график. Одновременно работает один тест.
  **«Остановить тест»** действует из любой вкладки.
- **Cache Speed**: жёлтая кривая чтения и зелёная кривая выполнения NOP-кода,
  чёрный график с бирюзовой сеткой, логарифмический размер рабочего набора.
  Пять опорных строк с минимумом, средним, максимумом и относительной скоростью.
- **Read RAM / Write RAM**: четыре цветные кривые для блоков **32 / 64 / 128 / 256
  байт**, ось пропуска между блоками и сводная таблица из четырёх строк.
  У записи фиолетовая сетка, у чтения бирюзовая. Наведение показывает точные
  скорости; выбор строки выделяет серию. Пунктир — сохранённый эталон.
- Прежняя структура сохранена: вкладки, график, сводка, таблица, настройки,
  кнопки запуска, эталона и экспорта. Под вкладками находится меню измерения:
  **«5 диапазонов · чтение и запись»** и классические Read/Write по размеру
  буфера доступны наряду с новыми вариантами. Latency сохранён.

Вид графиков основан на учебном образце. Алгоритм исходной Windows-программы
по фотографиям неизвестен: это самостоятельная адаптация для Mac, а не
обещание совпадения чисел или формы кривых. Никаких нарисованных ступеней,
сглаживания или искусственного «общего балла».

## Вкладки и методика

| Вкладка / вариант | Ось X | Что показывает график |
|---|---|---|
| Cache Speed → D-cache + I-cache | Рабочий набор, log₂ | Среднее чтения и NOP-кода, min–max |
| Cache Speed → 5 диапазонов | Рабочий набор, log₂ | Среднее чтения и записи, min–max |
| Read RAM → блоки | Пропуск между блоками, KiB | Медиана скорости каждого из четырёх блоков |
| Write RAM → блоки | Пропуск между блоками, KiB | Медиана скорости записи каждого блока |
| Read / Write → классический | Рабочий набор, log₂ | Медиана, min–max |
| Latency | Рабочий набор, log₂ | Задержка зависимого случайного чтения, ns/load |

GB/s = 10⁹ байт/с; размеры — двоичные KiB/MiB/GiB. Время измерения включает
работу циклов и расчёт адресов. Один фоновый поток, QoS User Initiated, macOS
сама выбирает ядро. Нет закрепления за P-ядром. Буфер выровнен, страницы
заполнены и прогреты до замера. Таймер монотонный. NEON/SSE2 обращения явно
сохранены в ассемблере; компилятор не удаляет нагрузку. Запись завершает барьер.
Лимит буфера — 1 GiB и ⅛ установленной RAM.

### Блоки и пропуски

- Размер буфера фиксирован настройкой **«До»**. Каждый проход обращается к
  блокам внутри этого буфера. Все четыре кривые используют один и тот же объём.
- **Шаг = размер блока + |пропуск|**. Ноль — последовательные неперекрывающиеся
  блоки. Положительный пропуск — обход вперёд, отрицательный — назад.
  Отрицательный проход обращается к тем же адресам, что положительный с тем же
  модулем: начинает с последнего помещающегося блока и заканчивает первым.
- 47 условий: −3072…7168 байт с интервалом 256, плюс ±32, ±64, ±128 возле нуля.
  Последовательность: пропуск по возрастанию, внутри него блоки 32/64/128/256.
- Число блоков за проход: `floor((buffer_bytes - block_bytes) / step) + 1`.
  Скорость считает **число блоков × размер блока**, исключая пропуски и остаток
  в конце. Это полезные явно обработанные байты, **не трафик DRAM** и не объём
  реально загруженных кэш-линий. Обход больших пропусков касается меньшей части
  буфера, поэтому даже большой буфер не гарантирует измерение чистой RAM.
- График — медиана повторов каждой точки. Таблица: минимум, максимум и среднее
  **медиан по всем 47 условиям**; «Подряд» — медиана при пропуске ноль.
  «Сред. / подряд» = среднее этих медиан / подряд × 100%. Это описательный
  показатель, он может превышать 100%. Он не означает КПД памяти или попадания
  в кэш. Процент появляется только после полного прогона.

### Профиль кэша и пять строк

Подробный график содержит 16 интервалов на удвоение: 225 размеров до 64 MiB,
257 до 256 MiB, 273 до 512 MiB, 289 до 1 GiB. Пять строк сводки — 4 KiB,
64 KiB, 1 MiB, 16 MiB и выбранный максимум. Это **опорные буферы, не уровни L1–L5**.
Сведения об аппаратных кэшах отдельно читаются из `sysctl` и показаны над вкладками.

В каждой строке — минимум, среднее и максимум **повторов этой точки**.
Процент = среднее / лучшее среднее той же операции среди пяти строк × 100%.
Промежуточные точки графика не меняют знаменатель. Для каждой операции свой максимум.

NOP-код создаётся локально (NOP + RET), ограничен **64 MiB** и измеряет
производительность последовательного исполнения инструкций. Его «GB/s» —
объём кода за секунду, **прокси фронтенда, не физическая пропускная способность
I-cache**. На графике и в таблице серия кода заканчивается на 64 MiB;
при большем максимуме соответствующая ячейка последней строки пуста.
Используется Apple MAP_JIT и entitlement `allow-jit`. При недоступности JIT
приложение показывает ошибку и сохраняет частичный результат.

### Latency и качество

Одна замкнутая случайно перемешанная цепочка указателей, узел через 128 байт.
Фиксированный генератор, равномерный выбор через rejection sampling, отдельный
прогрев. Каждый адрес зависит от предыдущего; проверки отмены через 1024 загрузки.
Время включает TLB, кэши, цикл и планировщик — это **не чистая задержка DRAM**.

| Профиль | Минимум времени одного повтора | Повторов |
|---|---|---|
| Быстрый / quick | 15 мс | 3 |
| Баланс / standard | 35 мс | 5 |
| Точный / precise | 60 мс | 9 |

Блоки: 188 точек, минимум ~8.5 / 33 / 102 секунды только на измерения.
Профиль 225 размеров с двумя операциями: ~20 / 79 / 243 секунды.
Подготовка, прогрев и интерфейс добавляют время. Вкладки остаются доступными.

Все повторы сохраняются. CV = population stddev / mean × 100%; >5% — подсказка
повторить тест, а не статистический критерий. Тепловое состояние и изменения
энергосбережения фиксируются в отчёте. Они не являются датчиками температуры
в градусах или доказательством троттлинга. Это не тест исправности RAM, GPU
или многопоточного максимума. Результаты разных методик напрямую не сравниваются.

## Эталон, экспорт и состояние

Каждый из семи экспериментов хранит отдельные результаты и настройки до закрытия
приложения. «Стоп» оставляет полностью измеренные точки. Экспорт во время теста
сохраняет **частичный снимок**; он не становится полным после завершения фонового теста.

«Сохранить как эталон» доступно только для полного результата. Файлы находятся в
`~/Library/Application Support/MemoryBenchmark/baseline-N.json`, индексы 0–3 и 5–7.
Старые эталоны 2.2 для прежних режимов сохранены; новые методы имеют отдельные файлы.
При загрузке проверяются полная сетка точек и координаты; статистика пересчитывается
из исходных повторов. Сохранение атомарное.

Сравнение требует одинаковых машины/ОС, метода, режима, объёма, профиля и питания.
Для новых режимов дополнительно сравнивается версия обхода (`sweep`). Пунктир —
совместимый эталон. Проценты в четырёхстрочной таблице блоков относятся к
последовательному доступу текущего прогона; в пятистрочной — к лучшей строке.
В классических Read/Write и Latency таблица показывает изменение к эталону.

Формат JSON GUI остаётся `schema_version: 2` с дополнительными полями:

- `metadata.mode`: `Cache Profile`, `Read Blocks`, `Write Blocks` или прежний режим;
- `metadata.sweep`: `cache-dense-v1`, `block-gap-v1` или прежний идентификатор;
- точка: `block_bytes`, `access_gap_bytes` (оба 0 в обычном профиле),
  `sample_values`, `median`, `mean`, `minimum`, `maximum`, `cv_percent`, единица;
- `block_summary`: четыре строки со статистикой условий и последовательной скоростью;
- `range_summary`: пять строк для профиля кэша и прежнего чтения/записи;
- `iterations` для блоков — число завершённых обходов выбранных адресов.

CSV GUI добавляет столбцы `block_bytes,access_gap_bytes,accessed_bytes_per_pass`.
`relative_speed_percent` в строках CSV по-прежнему относится только к пяти
опорным точкам размерного профиля; сводка блоков хранится отдельно в JSON.
Исходные повторы позволяют независимо пересчитать обе сводки.
CSV-комментарии начинаются с `#`: `pd.read_csv(path, comment='#')`.

## Сборка, CLI и проверки

```sh
xcode-select --install        # один раз для Apple Command Line Tools
bash build.sh                # собрать и открыть приложение
ARCH=universal MB_NO_OPEN=1 bash build.sh
bash test.sh
SANITIZE=1 bash test.sh       # ASan + UBSan на Linux
```

Можно открыть «Собрать и запустить.command». Готовая сборка —
`build/Memory Benchmark.app`; предыдущая сохраняется рядом с датой в имени.
Полный Xcode и Homebrew не нужны. Для проверок контрактов CLI нужен Python 3.

CLI сохраняет прежние четыре нагрузки и формат; новые блоковые эксперименты
доступны в GUI и через C API `mb_measure_blocks`:

```sh
./build/memory-bench --mode latency --max-mib 256 --profile precise --format json > latency.json
./build/memory-bench --mode all --max-mib 64 --quick > results.csv
./build/memory-bench --mode read --max-mib 256 --descending --samples 5 --seconds 0.035
```

`--samples 1..9`, `--seconds 0.001..1`; Ctrl+C оставляет валидный частичный JSON
и код завершения 130. Один повтор даёт CV=0 и не доказывает стабильность.

CI: Linux (включая санитайзеры), macOS Intel, сборка universal с `-Werror`,
проверка подписи и двух архитектур, Foundation/JSON/CSV, настоящие прогоны GUI,
переключение вкладок во время теста, отмена из «О программе», перезапуск,
сохранение/загрузка эталонов, светлые и тёмные снимки.
Нативный ARM-прогон включается отдельно через Run workflow → `native_arm64`.
Компиляция arm64 на Intel не означает проверку его исполнения.
Подробные результаты и границы проверки — [VALIDATION.md](VALIDATION.md).
