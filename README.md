# Memory Benchmark for Mac

Независимый аналог программы со скриншота: Cache Speed, Read RAM, Write RAM,
чёрный график с сеткой, реальные измерения и экспорт CSV. Подготовлен для
Apple Silicon, в том числе Apple M5. Минимальная целевая система — macOS 12.
Исходники также поддерживают Intel x86_64.

Программа не повторяет неизвестные алгоритмы оригинала. Числа со скриншота
не используются. Сравнивать её результаты с оригинальной программой напрямую нельзя.

## Совместимость

| Mac / система | Состояние версии 1.0 |
|---|---|
| Apple Silicon M1–M5, macOS 12 и новее | Готовая ARM64-сборка; запуск на этих моделях пока не проверен |
| Intel 64-bit, macOS 12 и новее | Поддержка в исходниках; нужна отдельная x86_64-сборка на Mac |
| macOS 11 Big Sur и более ранние версии | Текущая версия не поддерживает; понадобится адаптация и проверка |
| Старые 32-битные Intel / PowerPC | Не поддерживаются |
| Будущие модели Mac и будущие macOS | Совместимость ожидается при сохранении ARM64 и используемых API, но не гарантирована |

Минимальная цель сборки — **macOS 12 Monterey**: это указано в `Info.plist`
и `build.sh`. В коде используется `NSProcessInfo.lowPowerModeEnabled`, доступный
с macOS 12; простого изменения цифры в plist для более старых систем недостаточно.
Год выпуска Mac сам по себе не определяет совместимость: важны архитектура
процессора и установленная версия macOS. ARM64-приложение из архива не запускается
на Intel; на Intel скрипт `build.sh` автоматически собирает x86_64.

macOS 12 Monterey, 13 Ventura, 14 Sonoma, 15 Sequoia и 26 Tahoe находятся
в целевом диапазоне версии 1.0, **но это не список проверенных систем**.
На более новых системах ожидается работа за счёт обратной совместимости macOS;
новые ограничения безопасности или изменения API могут потребовать обновления.
Что проверено фактически, перечислено в [VALIDATION.md](VALIDATION.md).

## Запуск

Если в архиве есть `Memory Benchmark.app`, распакуй архив, перенеси приложение
в «Программы» и открой его. Выбери вкладку и нажми **«Начать тест»**.

Готовая сборка не имеет подписи Developer ID и нотариализации Apple.
Если macOS заблокирует открытие, после попытки запуска открой
**Системные настройки → Конфиденциальность и безопасность → Всё равно открыть**.
Отключать Gatekeeper или SIP не нужно. Альтернатива — локальная сборка ниже.
Сборка приложения сама по себе не подтверждает его запуск на конкретном Mac;
точные выполненные проверки описаны в `VALIDATION.md`.

## Сборка на твоём Mac

1. В Терминале один раз выполни `xcode-select --install` и дождись установки
   Apple Command Line Tools. Если они уже установлены, этот шаг не нужен.
2. Открой файл **«Собрать и запустить.command»** из папки с исходниками.
   Если запуск `.command` блокируется, открой Терминал, введи `bash `,
   перетащи туда `build.sh` из Finder и нажми Enter.
3. Скрипт соберёт нативное приложение, подпишет его локальной ad-hoc подписью,
   запустит тесты ядра и откроет `build/Memory Benchmark.app`.
4. Перетащи полученное приложение в «Программы». Python, Homebrew и полный Xcode
   не нужны. После сборки инструменты разработчика для запуска не требуются.

Скрипт использует только локальный компилятор и системные фреймворки. Не скачивает
зависимости, не требует `sudo`, не меняет настройки безопасности. Старый результат
сборки сохраняется рядом с датой в имени. На Apple Silicon по умолчанию собирается
arm64; при необходимости: `ARCH=x86_64 bash build.sh`.

## Что измеряется

| Вкладка | Измерение |
|---|---|
| Cache Speed | Чтение данных (жёлтая линия) и выполнение локального NOP-кода (зелёная) |
| Read RAM | Последовательное чтение всего буфера, от 4 KiB до выбранного предела |
| Write RAM | Последовательная кэшируемая запись всего буфера, тот же диапазон |

По горизонтали — размер **рабочего набора**, а не шаг доступа. Логарифмическая
шкала, четыре точки на удвоение. Скорости — в десятичных **GB/s = 10⁹ байт/с**;
размеры — в KiB/MiB/GiB. Не путать GB/s с гигабитами в секунду.

Методика **MBM-1.0**:

- Один фоновый поток, QoS User Initiated. macOS сама выбирает ядро.
- Память выровнена, заполнена до замера; есть отдельный прогрев.
- Чтение и запись используют явные 128-битные NEON/SSE2 инструкции.
  Компилятор не может удалить или заменить эти обращения к памяти.
- Для каждой точки — три замера, на графике медиана. Быстрый режим — минимум
  15 мс на замер, точный — 60 мс. Таблица и CSV содержат минимум/максимум.
- Запись завершается барьером памяти в конце каждого пакета проходов. Показана
  скорость записываемых полезных байтов; чтение для владения строкой кэша и
  прочий трафик не прибавляются к числителю. Это не гарантированная запись в DRAM.
- Таймер монотонный; измерение включает циклы, барьеры и задержки планировщика.
  Создание буфера и машинного кода в таймер не входят.
- Выполнение: ARM64 NOP (4 байта) или x86 NOP (1 байт), в конце RET.
  Размер кода / время обхода — **прокси для потока инструкций, не прямая
  пропускная способность I-cache**. Код ограничен 64 MiB; данные — 1 GiB.
  Инструкции генерируются только внутри приложения, никакой внешний код не загружается.

Небольшие буферы измеряют главным образом кэш. Буфер больше последнего кэша
лучше показывает поведение оперативной памяти, но размер системного кэша
может быть неизвестен. Программа не обещает его обход. Это не многопоточная
пиковая скорость памяти, не задержка случайного доступа и не тест неисправностей RAM.
Размеры кэшей берутся из `sysctl`; размеры групп P/E могут различаться, а L2
может быть общим. Неизвестные размеры и текущая частота CPU не выдумываются.

## Работа с результатами

- «Стоп» прекращает замер между пакетами проходов; завершённые точки остаются.
- У каждой вкладки свои результаты. Новый прогон заменяет результаты этой вкладки.
- «Экспорт CSV» сохраняет завершённые точки и настройки; неполный прогон помечается.
- Верхние строки CSV начинаются с `#` и содержат метаданные. При импорте в pandas
  используй `pd.read_csv(path, comment='#')`. В Numbers выбери запятую как разделитель.
- `sample_seconds` в строке — **сумма времени трёх замеров**, а `passes` — сумма
  проходов. Медиана скоростей не обязана равняться общему объёму / общему времени.
- Если создание исполняемого буфера недоступно, чтение продолжится, а отсутствие
  зелёной линии будет отмечено в статусе и метаданных CSV.

Для сопоставимых прогонов используй одну версию, настройки и режим питания.
Закрой тяжёлые приложения. MacBook Air без вентилятора может снижать частоту
при нагреве. Состояние энергосбережения и тепловое состояние включены в CSV.
Потребление памяти — примерно выбранный буфер плюс до 64 MiB кода и интерфейс.
Диск и сеть в тестах не используются.

## Командная строка и тесты

После локальной сборки:

```sh
./build/memory-bench --mode read --max-mib 256 > results.csv
./build/memory-bench --mode all --max-mib 64 --quick > quick.csv
bash test.sh
```

CLI по умолчанию использует 25 мс × 3; `--quick` — 5 мс × 3, поэтому профиль
CLI отличается от GUI и указан в stderr. Ctrl+C завершает CLI после текущей точки.
В Linux можно проверить ядро: `bash test.sh`; AppKit-интерфейс требует macOS.

## Исходники

- `Sources/benchmark.c`: измерительное ядро, NEON/SSE2, таймер, JIT, отмена.
- `Sources/main.m`: нативный интерфейс AppKit, график, таблица, CSV.
- `Sources/cli.c`: консольный интерфейс к тому же ядру.
- `Tests/test_core.c`: проверка диапазонов, результатов, повторов и отмены.
- `Resources`: метаданные приложения, значок, разрешение JIT для локальной сборки.

Реализация JIT следует механизму macOS `MAP_JIT` с переключением защиты записи
через `pthread_jit_write_protect_np` на arm64 и очисткой кэша инструкций.
Используется только `allow-jit`, без `jit-write-allowlist`.
Справка: [документация Apple](https://developer.apple.com/documentation/apple-silicon/porting-just-in-time-compilers-to-apple-silicon).
