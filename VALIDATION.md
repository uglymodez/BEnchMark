# Проверки версии 2.1

Компактный режим добавляет пять размеров буфера и чтение/запись с арифметическим
средним. Новые проверки: границы размеров, среднее, отличающееся от медианы,
раздельные знаменатели процентов, JSON/CSV, отсутствие процентов у частичных
прогонов, отклонение дубликатов и несовместимого старого эталона.

CI дополнен двумя реальными компактными прогонами с сохранением/восстановлением
эталона, проверкой пяти строк и процентов, экспортом и снимками обеих тем.
Результаты текущего запуска будут добавлены после его завершения.

Ниже сохранены сведения о предыдущей версии; они не заменяют проверку 2.1.

# Проверки Memory Lab 2.0 / MBM-2.0

## Локальная среда: Linux x86_64

- GCC, C11, `-O3 -Wall -Wextra -Werror`: сборка ядра, CLI и C-тестов.
- Диапазоны размеров и ошибочные параметры; чтение, запись, NOP-код и latency.
- Проверка единственного замкнутого цикла: все 128-байтные слоты посещаются
  ровно один раз, включая размеры, не являющиеся степенями двойки и повторное использование
  ранее выделенного большого буфера. Перестановка воспроизводится.
- Медиана (чётное и нечётное число замеров), population stddev и CV;
  проверка статистики по исходным значениям, все количества замеров 1–9.
- Отмена через атомарный флаг другого потока и сигнал CLI.
- CLI: 4 KiB–1 MiB, четыре операции; JSON/CSV, единицы, отдельные замеры,
  обратный порядок, ошибочные аргументы, корректный частичный JSON после SIGINT.
- AddressSanitizer + UBSan прошли локально с `detect_leaks=0`: LeakSanitizer
  в текущей локальной среде не работает из-за ptrace. В GitHub Actions на Linux
  полный запуск санитайзеров с настройками по умолчанию прошёл успешно.

## Автоматическая проверка macOS

[CI run 43878667975](https://github.com/uglymodez/BEnchMark/actions/runs/43878667975)
для коммита `6d8408c1c493a5710ea9957c10160f6ce36fe46f`: **все три задания прошли**.
Apple Silicon и Intel нативно выполнили тесты ядра, Foundation/JSON/CSV, сборку
AppKit с `-Werror`, проверку ad-hoc подписи и запуск GUI с latency-прогоном.
Артефакты приложения и снимки окна сформированы для обеих архитектур.

После визуальной проверки исправлен непрозрачный фон захвата и добавлены
повторный UI-прогон с восстановлением эталона, светлый/тёмный снимки и экспорт.
Эти дополнительные проверки должны пройти у финального коммита PR.

ARM-задания следующих прогонов не получили исполнителя GitHub и отменились
до запуска (например, run 43880808035, macOS 26: очередь 15 минут, ни одного шага).
Это ограничивает подтверждённое покрытие: финальные UI-изменения не проверены
исполнением на ARM. На Intel расширенный сценарий успешно прошёл, в том числе
сохранение/восстановление эталона, повторный прогон и визуальная проверка обеих тем.
JSON/CSV из GUI сверены: 57 одинаковых точек, медианы соответствуют исходным замерам.

Текущий workflow `.github/workflows/ci.yml` собирает **universal** на Mac Intel:

1. C-тесты, CLI и Foundation проверяются исполнением на Intel.
2. Apple Clang компилирует ARM64 и x86_64 части с `-Werror`; `lipo -verify_arch`
   проверяет наличие обеих архитектур. Выполняется `codesign --verify --strict`.
3. Universal-приложение запускается на Intel, выполняет два настоящих latency sweep,
   сохраняет/перечитывает эталон во временной папке и экспортирует JSON/CSV и снимки.
4. Один universal-архив приложения, CLI и отчёты публикуются как артефакт workflow.

Выполнение финальной версии на Apple Silicon остаётся отдельной проверкой:
Run workflow → `native_arm64` включает нативное ARM-задание, когда исполнитель
доступен. Успешная кросс-компиляция не называется успешным ARM-запуском.
Актуальный результат финального прогона приведён в PR и GitHub Actions.

## Что требует ручной проверки на Mac

- Внешний вид при изменении размера окна и в светлой/тёмной теме.
- Наведение на график, выбор строки, переключение вкладок, «Стоп».
- Сохранение эталона, повторный прогон, перезапуск и восстановление эталона.
- Диалоги экспорта CSV/JSON, открытие в Numbers и корректная реакция на отказ записи.
- Изменения питания/нагрева на реальном ноутбуке, работа с VoiceOver.
- Gatekeeper, Developer ID, нотариализация и разные модели Mac/версии macOS.

Архив `downloads/MemoryBenchmark-Mac.zip` остаётся сборкой 1.0. Проверки той версии не
переносятся автоматически на 2.0. Числа, полученные в Linux или CI, не встроены
в приложение как готовые результаты Mac пользователя.
